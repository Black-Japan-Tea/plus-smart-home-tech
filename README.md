## Описание проекта

Проект представляет собой распределенную систему, состоящую из независимых микросервисов, которые взаимодействуют друг с другом для обеспечения функциональности умного дома и электронной коммерции. Система построена на принципах микросервисной архитектуры с использованием современных технологий и паттернов проектирования.

## Структура проекта

Проект организован как Maven multi-module проект и состоит из трех основных модулей:

```
smart-home-tech/
├── commerce/              # Модуль электронной коммерции
│   ├── delivery/         # Сервис доставки
│   ├── interaction-api/  # API для взаимодействия между сервисами
│   ├── order/            # Сервис управления заказами
│   ├── payment/          # Сервис обработки платежей
│   ├── shopping-cart/   # Сервис корзины покупок
│   ├── shopping-store/   # Сервис магазина
│   └── warehouse/        # Сервис управления складом
│
├── infra/                # Инфраструктурные сервисы
│   ├── config-server/    # Сервер конфигурации (Spring Cloud Config)
│   ├── discovery-server/ # Сервер обнаружения сервисов (Eureka)
│   └── gateway/          # API Gateway (Spring Cloud Gateway)
│
└── telemetry/            # Модуль телеметрии
    ├── aggregator/       # Сервис агрегации данных
    ├── analyzer/         # Сервис анализа данных
    ├── collector/        # Сервис сбора данных
    └── serialization/    # Модуль сериализации
        ├── avro-schemas/ # Avro схемы
        └── proto-schemas/ # ProtoBuff схемы
```

## Архитектурные паттерны

### 1. Микросервисная архитектура (Microservices Architecture)

Проект построен на принципах микросервисной архитектуры, где каждый сервис:
- Имеет четко определенную область ответственности
- Развертывается независимо
- Может масштабироваться отдельно от других сервисов
- Использует собственные технологии и базы данных при необходимости

### 2. API Gateway

**Spring Cloud Gateway** используется как единая точка входа для всех клиентских запросов:
- Централизованная маршрутизация
- Унификация доступа к микросервисам
- Возможность добавления общих функций (аутентификация, логирование, мониторинг)

### 3. Service Discovery (Eureka)

**Netflix Eureka** обеспечивает автоматическое обнаружение сервисов:
- Динамическая регистрация и обнаружение сервисов
- Устранение необходимости жестко задавать адреса сервисов
- Поддержка балансировки нагрузки

### 4. Configuration Management (Spring Cloud Config)

Централизованное управление конфигурацией:
- Хранение конфигураций в едином месте
- Динамическое обновление конфигураций без перезапуска
- Поддержка различных профилей окружений

### 5. Event-Driven Architecture

**Apache Kafka** используется для асинхронной коммуникации между сервисами:
- Разделение производителей и потребителей событий
- Высокая пропускная способность
- Гарантия доставки сообщений
- Возможность обработки событий в реальном времени

### 6. Circuit Breaker (Resilience4j)

Паттерн Circuit Breaker для обеспечения отказоустойчивости:
- Защита от каскадных сбоев
- Автоматическое восстановление после сбоев
- Fallback механизмы при недоступности сервисов

### 7. Schema Registry

Использование Avro и Protocol Buffers для управления схемами данных:
- Версионирование схем
- Гарантия совместимости между версиями
- Эффективная сериализация/десериализация

### 8. Layered Architecture

Сервисы организованы по слоям:
- **Controller Layer** - обработка HTTP/gRPC запросов
- **Service Layer** - бизнес-логика
- **Repository Layer** - доступ к данным
- **DTO/Mapper Layer** - преобразование данных между слоями

- **Независимое развертывание**: изменения в одном сервисе не требуют перезапуска всей системы

- **Модульная структура**: четкое разделение ответственности между модулями
- **Централизованная конфигурация**: упрощение управления настройками

### 📊 Мониторинг и наблюдаемость

- **API документация**: автоматическая генерация документации через SpringDoc OpenAPI
- **Логирование**: структурированное логирование во всех сервисах
- **Метрики**: интеграция с Spring Boot Actuator для мониторинга

### 🔄 Современные практики разработки

- **Java 21**: использование последних возможностей языка
- **Spring Boot 3**: современная версия фреймворка с улучшенной производительностью
- **Docker Compose**: упрощение локальной разработки и тестирования
- **Maven Multi-Module**: эффективное управление зависимостями

## Структура модулей

### Commerce модуль

Модуль электронной коммерции включает следующие сервисы:

- **shopping-store**: Управление каталогом товаров
- **shopping-cart**: Управление корзиной покупок
- **warehouse**: Управление складскими запасами
- **order**: Обработка заказов
- **payment**: Обработка платежей
- **delivery**: Управление доставкой
- **interaction-api**: Общие API контракты для взаимодействия между сервисами

### Infra модуль

Инфраструктурные сервисы:

- **discovery-server**: Сервер обнаружения сервисов (Eureka Server)
- **config-server**: Сервер централизованной конфигурации
- **gateway**: API Gateway для маршрутизации запросов

### Telemetry модуль

Модуль сбора и обработки телеметрии:

- **collector**: Сбор данных от устройств умного дома (REST API и gRPC)
- **aggregator**: Агрегация и предобработка данных перед анализом
- **analyzer**: Анализ данных и сохранение результатов в PostgreSQL
- **serialization**: Модули с Avro и Protocol Buffers схемами

## API документация

После запуска сервисов, API документация доступна через SpringDoc OpenAPI:

- Swagger UI обычно доступен по адресу: `http://localhost:<port>/swagger-ui.html`
- OpenAPI спецификация: `http://localhost:<port>/v3/api-docs`

Каждый сервис, использующий SpringDoc, предоставляет свою собственную документацию.

## Разработка

### Структура кода

Проект следует стандартным соглашениям Spring Boot:

```
src/main/java/
└── ru/yandex/practicum/
    ├── controller/    # REST/gRPC контроллеры
    ├── service/       # Бизнес-логика
    ├── repository/    # Доступ к данным
    ├── dto/           # Data Transfer Objects
    ├── mapper/        # Мапперы для преобразования данных
    ├── config/        # Конфигурационные классы
    └── [Application].java  # Главный класс приложения
```

### Работа с Kafka

Kafka используется для асинхронной коммуникации между сервисами телеметрии. Основные топики:

- `telemetry.sensors.v1` - события от датчиков
- `telemetry.snapshots.v1` - снимки состояния устройств
- `telemetry.hubs.v1` - события от хабов умного дома

### Работа с gRPC

gRPC используется для высокопроизводительной коммуникации между сервисами. Схемы определены в модуле `proto-schemas` и автоматически генерируются при сборке проекта.

### Работа с Avro

Avro схемы определены в модуле `avro-schemas` и используются для сериализации данных в Kafka. Схемы автоматически генерируются при сборке проекта.
